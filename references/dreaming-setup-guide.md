# 后台信息助手设置向导

本文件定义 Dreaming 配置的 Agent 交互层。内部继续使用 Dreaming CLI 和 state；面向用户一律称为
“后台信息助手”，不得要求用户理解内部字段、job、grant 或宿主接入术语。

## 自然语言入口

以下意图都进入本向导，不要求用户说 `dreaming` 或记子命令：

- “帮我配置后台信息助手”“打开自动信息分析”“设置自动看飞书消息”
- “每天给我汇总重要信息”“有重要风险及时提醒我”
- “调整自动分析的频率 / 范围 / 摘要时间”“减少模型消耗”
- “为什么没有自动运行 / 没收到摘要”“继续刚才的设置”
- “暂停后台分析”“关闭自动提醒”

只问状态时先运行 `dreaming status` 并翻译回显；要求配置、启用、修复或继续设置时才进入后续步骤。
不得在普通 preflight、安装、升级或其它能力中主动推销本向导。

## 用户语言契约

交互选项、确认摘要、错误说明和最终状态卡禁止原样展示左列内部词。命令执行日志仅在排障细节中
按需展示，且先给自然语言结论。

| 内部概念 | 用户用语 | 必须解释的含义 |
|---|---|---|
| Dreaming | 后台信息助手 | 定期检查授权信息并整理待关注事项 |
| `enabled` | 后台分析开关 | 是否允许后台任务运行 |
| `operational` | 自动运行是否接通 | 本地定时任务是否已真实创建并成功触发 |
| harness | 本地定时任务 | Codex / TraeWork 桌面版在本机定期唤醒助手的任务 |
| process | 自动检查信息 | 按用户频率读取已授权来源并分析 |
| Finding / `persist_finding` | 待关注事项 / 保存分析结果 | 是否保留分析结果，供复查、摘要和后续反馈 |
| `persist_report` | 生成定时摘要 | 是否允许把已保存结果整理为本地晨报或周期报告 |
| `instant_alert` | 紧急事项及时提醒 | 是否允许高时效事项进入即时通知流程 |
| `archive` | 提议长期保存 | 是否允许重要内容成为待确认的长期知识候选 |
| maintenance | 自动健康检查 | 低频检查并修复确定性、低风险的索引或链接问题 |
| recovery | 离线后补跑 | 电脑恢复在线后补偿遗漏窗口或未完成投递 |
| `all_visible` | 全部可见会话 | 包含私聊和免打扰会话，必须单独确认 |
| `monitored` | 仅已选择的群聊 | 只读取已经登记的群聊范围 |

最终状态只使用“已开启 / 已关闭 / 待完成”，不得输出
`operational=false`、`harness=pending`、`persist_report=false`、`instant_alert=false` 等诊断串。

## 选项式交互

1. Codex / TraeWork 提供结构化提问或选项控件时必须优先使用；不可用时使用清晰的编号选项。
2. 一次只处理一个决策主题；最多并列三个紧密相关问题。不得把完整配置做成一大段问卷。
3. 推荐项放在第一位并说明适用场景；始终允许“自定义”和“暂不设置”。
4. 先运行 `dreaming status`，把现有选择映射为用户语言，再从第一个未完成或用户指定的步骤继续。
5. 所有选择先保存在当前对话中。执行写命令前展示一张自然语言配置摘要，并取得明确确认。
6. 用户只想修改一项时只问该项和受影响依赖，不强迫重走全部向导。
7. 用户中途离开时回显“已确认 / 尚未确认 / 下一步”，下次说“继续设置”可恢复。

## 快捷流程

- 暂停或关闭：先说明已保存的待关注事项和报告不会删除；用户确认后调用 `dreaming disable`。
  本地定时任务可以保留并安静退出，也可由用户在宿主中删除。最终只回显“后台信息助手：已关闭”。
- 恢复：读取原有选择，回显后只确认机器条件和恢复开关；不得静默扩大信息范围或提醒权限。
- 没有自动运行：优先检查本地定时任务是否接通、最近一次触发和下一次预计时间，再检查来源授权；
  不要先让用户重配全部选项。
- 没有收到摘要：区分“没有生成”“已生成但未投递”“本次没有值得汇总的内容”，不得把报告文件
  已写入等同于用户已收到。

## 分步配置

### 1. 使用目标

提供单选：

- “定期整理并给我摘要（推荐）”：保存分析结果并生成晨间摘要。
- “只整理，等我主动查看”：保存分析结果，不生成摘要或即时提醒。
- “只在紧急时提醒”：保存分析结果并允许高时效通知。
- “自定义”：逐项选择。

这一步只是形成后续问题的初始选择，不得直接写配置。

### 2. 自动检查频率

提供单选并说明模型消耗随频率增加：

- “每天固定时间一次（推荐）”
- “每小时或每几小时一次”
- “每几天一次”
- “自定义”

随后只询问必要的时间、间隔和时区。内部映射：

- 每几小时：`--process-kind interval --process-interval-minutes <N>`
- 每天：`--process-kind daily_time --process-time <HH:MM>`
- 每几天：`--process-kind every_n_days --process-every-days <N> --process-time <HH:MM>`

不得自行套用频率；推荐值也必须由用户点击或明确回复。

### 3. 信息范围

提供单选：

- “只看我已选择的群聊（推荐，范围更小）”
- “查看我能看到的全部会话”
- “暂不读取飞书消息”

选择全部会话时，必须再次明确说明“会包含私聊和免打扰会话”，取得单独确认后才能传
`--acknowledge-all-visible`。用户未确认时保持原范围，不得降级成模糊授权。

### 4. 结果如何给用户

使用多选：

- “保存待关注事项，之后可以复查”
- “工作日早上生成一份摘要”
- “高时效风险及时提醒”
- “重要内容可提议长期保存”
- “只运行分析，不保存结果”

依赖规则：

- 定时摘要、紧急提醒或长期保存都依赖“保存待关注事项”。若用户选择了依赖项但未选择保存，
  解释原因并请求补选，不得暗中开启。
- 定时摘要还要询问生成时间；当前产物先保存为 KB 本地报告。只有宿主返回真实投递回执时才能说
  “已送达”，否则只说“已生成”。
- 选择定时摘要后，再询问接收方式，可多选：
  - “在当前工具中显示摘要和详细报告链接（推荐）”
  - “同时通过飞书应用机器人发给我”
  当前工具无论是 TraeWork、Codex 还是 Claude Code，都只消费本地报告文件；支持 HTML 预览时
  可直接打开，不支持时给出本地文件链接，不能要求宿主提供专用接口。
- 选择飞书时，优先让用户填写日常使用的字母用户名（如 `ranjiao`）；配置层通过 user 身份的
  通讯录查询唯一解析并复验 open_id，状态中保存 open_id 和用于展示的原始用户名。也兼容直接
  输入 `ou_`。无法唯一确认时保持“待完成”，不得猜收件人或发送测试消息。飞书只发送
  300–500 字摘要，详细内容仍通过本地 HTML 查看。
- 选择定时摘要时内部设置 `--morning-enabled true --morning-time <HH:MM>` 并传
  `--persist-report`；关闭摘要时关闭 morning job。只有没有其它周期报告依赖时，才同时关闭报告
  写入授权。
- 紧急提醒只是允许进入通知流程；本地定时任务和投递渠道未接通前，必须显示“待完成”。
- “只运行分析，不保存结果”意味着本次分析结束后不能复查、生成摘要或触发后续提醒，必须在确认
  摘要中明确提示。
- Todo、来源订阅、冲突处理和长期知识写入仍逐项确认，不因本步骤自动执行。

内部写入时重建完整 grant：

```bash
bin/byteworker dreaming grant set-im --kb "<KB>" --mode <mode> [--persist-finding] \
  [--acknowledge-all-visible]
bin/byteworker dreaming grant set-actions --kb "<KB>" \
  [--persist-report] [--archive] [--instant-alert]
```

`set-im` 和 `set-actions` 的未传 flag 表示关闭。只改一个选项时必须先从 status 保留其它已确认项，
不得因命令覆盖语义意外关闭用户原设置。

### 5. 后台保障

提供两个独立开关：

- “自动健康检查（推荐）”：只修复确定性、低风险问题，其它问题请用户决定。
- “离线后补跑（推荐）”：电脑恢复在线后补偿遗漏窗口；不承诺休眠期间准点运行。

再询问运行记录保留期，推荐 30 天，可选 7 / 30 / 90 / 自定义天数。

### 6. 确认并应用

用用户语言展示：

- 自动检查频率和下一次预计时间
- 信息范围，是否包含私聊和免打扰
- 是否保存分析结果
- 摘要时间、紧急提醒、长期保存建议
- 自动健康检查、离线后补跑、运行记录保留期
- 本地机器需开机、唤醒、联网，以及额外网络、模型和存储开销

用户明确确认后，按顺序执行：

1. `dreaming configure`
2. `dreaming grant set-im`
3. `dreaming grant set-actions`
4. 首次开启时执行带三项 acknowledgement 的 `dreaming enable`
5. `dreaming status` 复验

若用户选择飞书接收，在第 1 步同时写入已确认的飞书收件设置；未选飞书则保持关闭。宿主结果
展示始终开启，不需要为不同宿主保存不同配置。

任一步失败都停止后续写入，使用自然语言说明哪项未生效，并保留已确认选择供重试。不得把部分
成功描述为“设置完成”。

### 7. 接通自动运行

控制面开启不等于会自动运行。Codex / TraeWork 有真实任务工具时，用用户刚确认的设置创建本地
任务并首次触发；没有工具时按对应 harness reference 引导用户操作。TRAE 产品家族使用
`references/dreaming-harness-trae.md` 先分流：TRAE IDE/TraeCode 提示切换，TraeWork 桌面版
才能接通本地自动运行。

创建或修改本地定时任务前，必须确认“本地任务唤醒间隔”：只唤醒 runner 查 due，不等于业务分析
频率或每次都调用模型。推荐 2 小时；用户可按 quota 和时效调整。已有任务只改间隔。

只有任务真实存在、首次触发成功并完成 register 后，才显示：

> 自动运行：已接通

否则显示：

> 自动运行：待完成。设置已经保存，但还不会按时自动执行。

## 完成状态卡

设置结束只展示以下用户字段：

```text
后台信息助手：已开启 / 已关闭
自动运行：已接通 / 待完成
任务唤醒：<间隔> / 待设置
信息范围：仅已选择群聊 / 全部可见会话 / 未授权
自动检查：<自然语言频率与时间>
分析结果：保存 / 不保存
定时摘要：<时间> / 关闭 / 待完成
摘要接收：当前工具 / 当前工具 + 飞书 / 待完成
紧急提醒：开启 / 关闭 / 待完成
自动健康检查：开启 / 关闭
离线后补跑：开启 / 关闭
运行记录：保留 <N> 天
下一次预计运行：<本地时间或“自动运行接通后计算”>
```

不要附加原始 status JSON。用户主动要求技术细节或排障时，才在该状态卡之后给内部字段和命令。
