# Byteworker 用法

可以直接说你想做什么，也可以用 `/byteworker <子命令> [参数]`。

## 保存和查询资料

| 想做什么 | 可以这样说 | 子命令 |
| --- | --- | --- |
| 保存资料 | 「把这份飞书文档存进知识库」或「把这个群最近一周的讨论存进来」 | `digest` |
| 查以前的决定或进展 | 「这个项目现在怎么样？上次定了什么？」 | `search` |
| 补充新情况 | 「更新这个项目的进展」或「这条我重新核实过了」 | `update` |
| 保存自己的想法 | 「把刚才关于这个方案的判断和假设记下来」 | `thinking` |
| 复查定期来源 | 「跑定期摄取」 | |

可保存的资料包括飞书文档、妙记、会议、群聊、Meego 保存视图、多维表格视图、风神看板、外部文章和本地 Markdown。查项目或决策时，回答会附原始出处、原文时间、收录时间和置信度。也可以用 ID 或标题查已收录的 Meego、多维表格或风神记录。

## 准备会议和跟进工作

| 想做什么 | 可以这样说 | 子命令 |
| --- | --- | --- |
| 看会前简报 | 「看看今天的飞书日历，帮我准备会前简报」 | `brief` |
| 看工作看板 | 「打开看板」「把这个项目设为长期关注」或「加一条看板提醒」 | `dashboard` |
| 更新个人工作偏好 | 「我现在的工作重点改成 X」或「默认提醒时间改成上午十点」 | `context` |
| 找到当前可用的功能 | 「Byteworker 还能帮我做什么？」 | |

看板会汇总长期关注、需关注事项和今日进展。任务成功后，Byteworker 偶尔会给一条相关建议。你可以说「以后再说」「别再提示这个」或「关闭功能建议」。

## 定时报告和后台检查

说「设置自动报告」可以创建本地定时任务。默认在工作日 20:30 生成日报，在周一 09:30 生成上一完整 ISO 周的周报，时间可以调整。每次先更新已登记的定期来源，再生成报告。设备恢复后可检查并补跑错过的报告。也可以说「补生成 2026-05-25 的日报」，或「修改自动报告」「暂停自动报告」。

说「帮我配置 Dreaming」可以设置检查范围、频率、摘要和紧急提醒。Dreaming 默认关闭，启用前会说明授权、成本和运行条件，并请你确认。定时任务需要设备开机、唤醒且联网。说「分析今天的飞书聊天」只运行一次，Dreaming 保持原来的后台设置。想核对结果，可以说「看看待关注事项」或「为什么认为这条重要」。

## 浏览、引导和排障

- **浏览知识库**。在本地安装目录运行 `bin/browse.sh`，用浏览器看笔记、原文和报告。云端会话可以直接在对话中查询。
- **重走上手引导**。说「跑一下上手引导」。可以跳过摄取和查询演示。
- **检查知识库**。用 `/byteworker doctor` 或说「升级后检查一下知识库」。检查默认只读。明确要求修复时，才会执行支持的索引和链接修复。
- **反馈问题**。说「反馈刚才的摄取问题」会生成供你检查的邮件草稿。说「导出这次摄取的诊断包」会生成仅含技术诊断信息的本地 ZIP。
- **检查更新**。说「更新 skill」或「检查更新」。成功检查后七天内会跳过重复检查。代码有更新时会检查知识库兼容性。需要固定版本时，可以设置 `BYTEWORKER_NO_AUTO_UPDATE=1`。

知识库保存在你指定的独立目录，禁止外传或提交到 skill 仓库。
