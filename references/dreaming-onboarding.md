# Dreaming 启用前能力导览

只在用户准备启用 Dreaming 时加载。不能只展示一句成本提示；必须用自然语言完整讲清以下内容，
允许用户追问，并在导览结束后单独询问是否启用。

实际配置对话必须同时读取 `references/dreaming-setup-guide.md`，使用其中的结构化选项、分步恢复
和用户语言契约。面向用户称为“后台信息助手”，不得要求用户理解 Dreaming 的内部字段名。

## 它与 digest 的区别

| | digest | Dreaming |
|---|---|---|
| 触发 | 用户给出明确资料或运行 routine | 宿主定时唤醒，主动检查已授权来源 |
| 目标 | 把一份资料可靠摄取为 raw、出处和实体图 | 发现变化、形成 Finding、报告或待确认动作 |
| 写知识 | 通过 SourceBundle + DigestTxn 直接完成 | 默认不入库；知识候选仍须重新采集并走 DigestTxn |
| 生命周期 | 一次事务，committed/noop 即结束 | 长期 job、lease、cursor、Finding、feedback 和 recovery |

Dreaming 不是“自动 digest 所有内容”，也不替代 search/update/todo。

## 能做什么

1. 自动检查信息：按用户选择的范围读取来源，识别决策、责任、风险、变化和冲突，整理为可复查
   的待关注事项。
2. 复查与反馈：查看为什么重要、信息覆盖范围，并标记有用、已知、错误、完成、延后或忽略。
3. 定时摘要：基于已保存的待关注事项、个人待办和知识库生成晨间摘要；日报和周报只有完成单独
   迁移后才会接管。
4. 受控后续动作：报告、提醒、待办候选、来源候选和长期知识候选都先经过权限与确认；默认不会
   自动发消息、建任务或写长期知识。
5. 自动健康检查：低频修复索引、明确链接等确定性低风险问题；其余重要问题只给有限摘要，请
   用户决策，不猜业务语义。
6. 离线后补跑：补偿电脑离线期间遗漏的窗口、未完成处理或待投递事项。

## 默认值与授权

- 启用前必须展示并让用户配置完整运行计划，不能因为存在推荐值就跳过确认。
- 自动检查支持每隔一段时间、每天固定时间、每几天固定时间三类频率。
- 信息范围默认不读取飞书消息。“只看已选择群聊”和“全部可见会话”必须由用户选择；后者包含
  私聊和免打扰会话，需要再次确认。
- 保存分析结果、生成定时摘要、紧急提醒和提议长期保存分别授权。待办、来源、冲突和长期知识
  候选仍可要求逐项确认。
- 用户主动执行一次分析不等于启用后台，也不会继承后台的信息范围。

## 成本、隐私与运行条件

- 会增加网络请求、模型 Token、私密 spool/state 和报告存储；具体消耗随来源量和频率变化。
- 本地机器和宿主任务必须保持开机、唤醒、联网；休眠/关机期间不运行，恢复后只能补跑。
- state 位于 KB 的 Git 排除目录，权限为 `0700/0600`；业务数据不进入 skill 仓库、不 push。
- 每个后台 lease 产生稳定 `run_id` 和私有 JSONL 运行日志，包含阶段、heartbeat、耗时、有限计数
  和 error code，不包含消息正文。日志默认保留 30 天，可在 1..365 天内配置。
- coverage 不完整会明确标 partial；Dreaming 故障不阻塞 digest/search/update。

## 启用前对话

导览后按 `references/dreaming-setup-guide.md` 依次完成：

1. 用户是否理解它是长期主动机制而非 digest 的快捷模式。
2. 用选项逐项配置时区、自动检查频率、摘要时间、自动健康检查、离线补跑和运行记录保留期；
   说明模型消耗与运行频率的直接关系。
3. 用选项确认信息范围、是否保存分析结果、定时摘要、紧急提醒和长期保存建议；依赖项必须解释，
   不得暗中代开。
4. 是否接受机器运行条件与额外网络、模型、存储成本。
5. 是否现在启用。只有明确同意后才能同时传：
   `--acknowledge-capability-tour --acknowledge-schedule --acknowledge-machine-runtime`。

内部复验仍检查 enabled、harness、operational 和各 job 的 `next_due_at`，但用户回显必须使用
设置向导定义的状态卡。真实本地定时任务尚未创建和首次触发时，明确显示“自动运行：待完成；
设置已经保存，但还不会按时自动执行”，不得输出内部诊断串或声称已经完成。

当前环境或用户选择的宿主属于 TRAE 产品家族时，额外加载
`references/dreaming-harness-trae.md` 并先区分具体产品。TRAE IDE/TraeCode 不能创建所需的
本地定时任务，必须提示用户切换到 TraeWork 桌面版；只有确认处于 TraeWork 桌面版后，才能调用
Schedule 工具或逐步引导用户创建本地 Code 自动化任务并首次触发。不能把控制面已开启当成任务
已创建。
