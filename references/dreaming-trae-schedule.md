# Trae Dreaming 定时任务

用户要求在 Trae 创建、接通或恢复 Dreaming 定时任务，或索要手动新建用的 prompt 时，加载本文件。
Trae 原生定时任务支持对话创建和手动新建。创建时检查当前会话能否调用原生任务工具，以及
实际运行环境能否访问本地知识库、Byteworker 安装目录和所需的用户态工具。
[Trae 定时任务文档](https://docs.trae.cn/work_automated-tasks)

## 生成任务内容

用当前选定的知识库绝对路径和实际 Byteworker 安装目录填充下方模板。创建请求先用 `dreaming status`
检查现有设置和任务登记，并用已经确认的配置继续。只索要 prompt 时可直接给草稿，无需启用或写入
配置。已知路径须填入；无法确定的值保留为占位，指出粘贴前要替换。实际创建前须补齐所有值。

默认任务名称为 `byteworker-dreaming-local`。同一宿主有多个知识库时为每个库选不同的稳定名称。
已存在的同库任务继续沿用原标识。新任务创建前用选定的任务名称绑定 runner 的 `<TASK_ID>`；原生工具
返回的宿主 ID 用于查询任务和运行记录。登记时使用与 runner `--owner` 完全一致的 `<TASK_ID>`。

把以下内容渲染成一整段可复制的代码块。只填本地路径与任务标识，禁止加入凭据、消息或业务正文。

```text
你正在执行一个本地 Byteworker Dreaming 定时任务。每次唤醒时，读取 <BYTEWORKER_REPO>/templates/dreaming-runner.md，并按其中的无人值守流程运行一轮。
本地工作目录和知识库绝对路径均为 <KB>，任务标识为 <TASK_ID>。执行模板里的命令时，将知识库路径传给 --kb，将任务标识传给 --owner，并通过 <BYTEWORKER_REPO>/bin/byteworker 的绝对路径调用 Byteworker。
沿用已确认的 Dreaming 配置和来源授权。由 dreaming tick 判定什么任务已到期，按 runner 完成并回报本轮结果。
```

将以下表单设置放在代码块外：任务名称、Code 模式、本地环境、KB 工作目录（或选用包含 KB 的本地项目）、本机私有输出位置，
以及用户确认的唤醒间隔和时区。Trae 只负责按间隔唤醒，业务频率仍在 Dreaming 设置中管理。
优先使用已配置的 `harness_preferences.wake_interval_minutes`，最短 5 分钟。未确认时可在草稿中给
出 2 小时的建议，按已选任务的时间要求调整。实际创建前须确认间隔，确保所需的执行时段内有唤醒机会。

## 日报截止触发

已接管日报的知识库可使用宿主支持的独立本地定时入口，在工作日的计划出报时间调用
`<BYTEWORKER_REPO>/bin/byteworker dreaming report publish-due --kb "<KB>"`。
确认该入口能和长 Agent 会话并行启动。常规间隔任务也会检查到期日报，迟到时保留事故记录。
宿主只有间隔唤醒或无法并行时，实际出报时间受下一次可用唤醒约束。

## 创建与复验

接通自动运行前，按 `references/dreaming-setup-guide.md` 完成尚未确认的设置及首次启用导览。

1. 用户只索要 prompt 或选择手动新建时，给出上面的任务内容和表单设置。指明把代码块粘贴到
   Trae 左栏「自动化」→「手动新建」的「任务内容」栏。只索要 prompt 到这里即可。
2. 用户要求 Agent 创建且本地原生任务工具可用时，先用本地登记和可查询的 Trae 任务核对同库任务。
   已有任务继续复验，否则按已确认的表单设置提交同一份 prompt。工具不可用或明确未创建时交付手动
   步骤。工具返回超时或结果不明时，先查询任务状态，无法查清时请用户先检查 Trae 的「已配置」列表，
   再决定是否手动新建。
3. 任务创建后，若宿主工具提供立即运行能力，由 Agent 触发并核对执行记录。否则，由用户通过 Trae
   触发或等首次触发。结合 Trae 任务记录与 `dreaming diagnose` 核实本次运行确实通过了
   `dreaming tick`。没有到期工作而正常结束也算通过。任务只出现在列表中、等待授权、启动失败或
   缺少执行证据时保持「自动运行：待完成」。
4. 确认创建和首次触发均通过后，执行 `dreaming harness register --kb "<KB>" --task-id "<TASK_ID>"`，
   再用 `dreaming status` 确认已接通。登记和验证由交互会话完成，定时任务只调用 runner。

用户要求创建时，最终回复一并提供可粘贴的任务内容与当前状态。有本地能力但尚待用户操作时，说明需
完成的具体一步。只有云端环境或运行目录权限不足时，说明本地运行条件并保留 prompt 供手动接通。
