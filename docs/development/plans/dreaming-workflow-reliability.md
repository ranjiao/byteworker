# Dreaming 日报保障与任务恢复方案

工作日日报到点后必须有一份可打开的归档。先使用当时已经核验的材料，待处理完成后补充同一期。单个来源失败、模型处理超时或资料缺失只影响覆盖程度。到期无归档属于最高级别事故，之后补成功也要保留迟报记录。

来源处理可以跑一小时或更久。活跃任务应继续推进，已完成的采集、分片和提交需要支持跨进程接手。Dreaming 可以在现有公开命令上统一依赖检查、任务领取、回执验收和恢复，保留 Digest、IM、知识库事务各自的领域规则。

## 当前实施范围

已增加独立 Markdown 日报、发布重放、按期事故记录、近 14 天的同周期补充，以及 process 心跳续租和过期接手。沿用现有本地状态、批次与回执，未迁移到规划中的 SQLite 协调器。完整的逐阶段 DAG 调度和真实宿主独立唤醒仍需验收。以下现状表保留为改造前的故障基线。

## 当前流程审计

| 环节 | 当前行为与风险 | 证据 |
| --- | --- | --- |
| 宿主唤醒 | 宿主按间隔启动任务，一次至多领取一项。入口先跑预检，再启动调度器。两次子进程调用均未设超时。没有唤醒或预检卡住时，系统无法在截止点兑现日报。 | [宿主约定](../../../references/dreaming-trae-schedule.md#创建与复验) · [唤醒入口](../../../lib/dreaming_diagnostics.py#L21) |
| 任务争用 | 知识库只有一个活动租约。租约被占用时，调度器在枚举日报周期前返回 `busy`。日报优先级只在执行槽空闲时生效。普通摄取结束后，runner 通常直接结束，只有成功的 catch-up 才立即尝试续领。 | [领取](../../../lib/dreaming_scheduler.py#L1407) · [Runner 收尾](../../../templates/dreaming-runner.md#L58) |
| 长任务与接手 | 心跳更新阶段和时间。续租是独立命令，模板只要求定时写心跳。过期后按新 run ID 建批次，原批次的关联和窗口留在原运行里。内容和计划匹配时能复用部分语义分片。通用收尾和报告发布还有不同的租约过期检查。 | [续租与心跳](../../../lib/dreaming_scheduler.py#L1791) · [通用收尾](../../../lib/dreaming_scheduler.py#L1998) · [批次关联](../../../lib/dreaming_digest.py#L320) |
| 来源调度 | 扫描按波次等待，每个公开子命令有独立超时。Runner 等扫描返回后才推进语义分析，定期来源收尾之后才开始下一段 IM。一个慢来源会延迟已经就绪的其他工作。 | [扫描](../../../lib/dreaming_digest_scan.py#L122) · [Runner 顺序](../../../templates/dreaming-runner.md#L15) |
| 摄取验收 | 当前工作区已能找回同一批次内漏登记的下游回执，并拦住缺少回执的收尾。检查点仍在整批收尾时推进。批次被中断，或任一来源 Profile 变化时，已完成的其他来源不会在该次收尾推进覆盖。检查点和批次记录分两次替换落盘。 | [批次收尾](../../../lib/dreaming_digest.py#L953) |
| IM 提交与报告输入 | IM 先写 Finding history，再写批次提交标记。报告从 history 重建投影，只按时间筛选。进程在两步之间中断时，日报可读取尚无批次提交回执的 Finding。 | [IM 提交](../../../lib/dreaming_process.py#L146) · [提交标记与恢复](../../../lib/dreaming_batch.py#L297) · [报告输入](../../../lib/dreaming_reports.py#L309) |
| 日报产物 | 流程需要 Agent 生成合法报告 JSON，再顺次写私有文件、HTML、Markdown 归档和清单，最后记录任务状态。HTML 失败会挡住 Markdown。归档与清单之间也存在崩溃窗口。调度枚举部分场景以 Markdown 文件存在为依据，缺少统一发布凭证。 | [渲染与归档](../../../lib/dreaming_report_bundle.py#L654) · [周期枚举](../../../lib/dreaming_scheduler.py#L1105) |
| 重试与补充 | 退避存在 job 级状态中，上一期失败可延迟新到期的日报。正式归档会清除待发布周期，普通摄取完成后没有按受影响日报自动补充的步骤。飞书投递已有独立队列。 | [任务门槛](../../../lib/dreaming_scheduler.py#L1132) · [归档与退避](../../../lib/dreaming_scheduler.py#L2214) · [投递](../../../lib/dreaming_report_completion.py#L68) |

最近的事故涉及两类验收。来源已提交但父流程没收到回执，需要对账恢复。非空窗口没有可入库事实，需要实际归档或等值证据才能推进覆盖。只把日志标成 `noop` 无法证明其中任何一种。当前修补保护了同一批次的收尾，跨运行接手仍缺少统一流程。

## 临时库复现

| 场景 | 实测结果 |
| --- | --- |
| 摄取跨过日报时间 | 到点唤醒返回 `busy`，当期日报未进入待处理周期。摄取结束后日报仍不存在，直至模拟下一次显式领取才选到日报。 |
| 心跳临近到期 | 测试租约为 60 分钟。第 59 分钟的心跳未延长租约。第 61 分钟心跳被拒，同一过期 token 却能在下一次领取前走通用成功收尾。 |
| 上一轮租约过期 | 新运行创建了不同截止时间和 run ID 的批次。旧批次仍显示 `running`，新批次来源为 `pending`，没有接手旧工作。 |
| 报告渲染中断 | 注入 HTML 错误，私有 JSON、摘要与 Markdown 已写，正式 Markdown 未归档。同一有效租约重试可成功。注入清单写入错误时，正式 Markdown 已存在，但没有清单，任务仍待完成。 |
| 旧日报影响新日报 | 前一期在当期截止前一分钟失败。到点时当期已进入待发布，整个日报 job 却处于退避，调度返回 `idle`。 |
| IM 中断于正式提交前 | 写入合成 Finding 后停在批次提交前。没有 `batch.commit.json`，日报 packet 仍返回 1 条 Finding。 |

真实知识库的运行记录用于核对事故顺序。以上复现均使用临时合成数据。

## 任务依赖与推进

```mermaid
flowchart LR
    A["日报截止时间"] --> F["生成基础日报"]
    B["来源和 IM 分窗"] --> C["采集与核验"]
    C --> D["分析与分片检查点"]
    D --> E["提交并验收回执"]
    E -. 取截止时已验收的材料 .-> F
    F --> G["原子发布 Markdown"]
    E --> H["按原文时间匹配受影响日报"]
    G --> H
    H --> I["同一期补充版本"]
    G -. 独立派生 .-> J["HTML 与可选投递"]
```

- **日报有独立的执行槽。** 宿主在日报截止点触发报告，周期唤醒继续推进摄取与恢复。两个入口共享发布去重。即使宿主串行执行 Agent 会话，基础日报也需要能从单独的本地执行入口生成。基础版从已验收的快照确定性生成 Markdown。模型总结、HTML 和飞书另行推进。
- **记录并检查期限。** 每期记录计划时间、窗口起止、初版发布时间和最近补充时间。普通来源缺失时归档并说明覆盖。磁盘不可写、资料授权或完整性无法验证时，记录具体事故，条件恢复后继续。没有宿主唤醒时，在下次检查识别并记录漏报。若要求主机离线时即时告警，需要独立的在线监控。
- **明确硬依赖和软依赖。** 分页完整、分析结果和输入一致、写入授权有效，属于相关节点的硬依赖。未验收的来源对日报属于软依赖。可用材料为空时，初版说明当期尚无可核实信息和覆盖缺口。有材料时呈现事实摘录与出处。
- **按工作项独立领取。** 来源项以来源身份、Profile 版本和窗口标识，日报以知识库、类型和周期标识。一个工作项可以有多次执行尝试，每次持有独立租约。来源、IM 分窗和语义分片分别就绪、分别推进。并发读受 provider 和宿主容量控制，最终知识写入沿用现有锁。
- **长任务自动续租，失效后接手。** 执行器在可观测的长调用期间续租，并用独立信号判断进度停滞或执行者消失。到期收回本次执行权，保留工作和已验收回执。接手者先对账，再只重试未完成节点。过期执行者无法确认阶段，也不能再发起受管写入。到期前已提交的副作用靠回执重放。
- **回执决定验收。** 采集核验窗口、分页及身份，分析核验输入和分片回执，提交核验 Git、原始证据或 IM commit marker。阶段回传可幂等。来源回执通过后独立推进覆盖。单个 Profile 失效只隔离对应来源。失败状态区分可重试、等待授权和重大阻塞。
- **日报只读已验收快照。** IM 只有提交标记可核对的事件进入出报投影。知识库读取关联已确认的 Git 版本或等价的只读快照。时间窗在周期登记时固定，晚到资料按原文时间补充受影响的周期。补充版本去重并保留手动备注，失败时保留最新已发布版本。
- **Markdown 发布有一个验收点。** 先写带校验值的不可变版本，核验后原子切换当前版本。切换后、任务收尾前中断时可对账。发布凭证验证正确周期、可读归档和当前版本。HTML 预览和飞书投递各自记录结果。

### 并发与先后顺序

- 日报截止时间优先于一切可延后的工作。晨报保留中午截止，周报保持自己的覆盖规则。维护与历史恢复使用可分配的后台容量。明确给历史欠账留进度，避免每次近期任务到期就把它剔除。
- 一次部分完成只给失败工作项退避。近期摄取仍可按计划领取新的窗口。防止同一坏来源让整轮长期反复扫描。历史 IM 继续遵守 14 天自动回看限制，超过期限的缺口保留原因和未覆盖状态。[当前候选策略](../../../lib/dreaming_scheduler.py#L1540) · [当前恢复窗口](../../../lib/dreaming_collection.py#L26)
- 同一来源的增量窗口按已验收进度衔接。不同来源、无依赖分片和分开的 IM 窗口可并行。对同一知识实体的候选提交仍按现有事务锁和冲突规则验收。日报从不可变快照读取，无需等正在分析或等待提交的工作结束。

### 持久化边界

采用小型、持久化的应用内任务 DAG。工作流模板定义阶段和依赖，协调器检查就绪条件、领取、恢复及收尾。Agent 执行需要判断的节点，提交候选和证据。DigestTxn、IM 提交和报告发布各自继续验证领域回执。

协调器只保存稳定任务键、尝试、依赖、回执引用、时间和原因码。单机可用本地 SQLite，在同一事务内更新任务、租约、回执引用和就绪状态。Git 和文件归档仍是独立写入边界，由各自可核验的提交凭证对账。业务正文留在现有知识库。保留公开命令作为兼容入口。旧产物和检查点按可核对的凭证导入，先影子调度比较结果，再切换唯一发布者。

## 实施顺序与验收

1. **先保障日报。** 将周期登记移到占用判断前，增加独立到点触发、基础 Markdown、发布凭证和漏报记录。仅纳入能核对提交凭证的输入，退避按周期保存。旧摄取继续运行。下表前五项与 IM 提交前不可见的检查通过后交付。
2. **再拆持久摄取工作项。** 逐来源和窗口领取、自动续租、统一过期校验、跨尝试恢复、提交对账和逐来源推进覆盖。完成 IM 提交标记与投影的恢复对账。先做合成故障测试，再与实际调度影子比对。
3. **接通自动补充。** 用来源回执和发生时间找到需修订的日报。使用同周期的版本、快照和去重键。验证迁移与恢复后，移除旧的临时跟进路径。

| 验收场景 | 通过标准 |
| --- | --- |
| 摄取运行 90 分钟并跨过截止时间 | 截止时独立执行基础日报，摄取不中止、不重做。 |
| 所有新来源失败，或模型、HTML、飞书不可用 | 可写盘时仍发布可打开的 Markdown。已有事实有出处。材料为空时记录缺口。HTML 和投递各自重试或跳过。 |
| 双重唤醒与跨期退避 | 同一期只产生一个有效初版，旧日报退避不妨碍新日报。两期都待发布时优先当期。 |
| 发布各写入点中断 | 分别在版本写前、写完、切换指针和任务收尾时中断。重启能从凭证续办并保留上一份可读版本。 |
| 宿主错过截止或磁盘不可写 | 记录迟报和原因，条件恢复后补发并保留事故记录。状态不会显示不存在的成功产物。 |
| 执行者存活超过两小时或处理中被终止 | 有效执行持续续租。终止后换执行者和租约版本，复用已核验产物。旧 token 无法推进受管状态。 |
| 三个来源提交后进程退出，或只修改其中一个 Profile | 接手后核验已提交回执，其他来源的覆盖不回滚。只重试缺失或受变更影响的节点。 |
| 快来源先完成、慢来源等待，近期任务持续到来 | 快来源先分析并验收，慢来源可继续。历史可恢复欠账仍能推进。 |
| 群聊空窗口、等值窗口和非空无新增事实 | 分别生成可验证的空窗口、等值复用或实际归档凭证。成功日志本身无法推进覆盖。 |
| IM 在 Finding 写入后、标记写入前退出 | 该 Finding 不进入日报。标记写入后的中断可对账，恢复后恰好一次进入报告投影。 |
| 迟到材料横跨多个周期 | 只修订实际受影响的日报。重复回执不重复写事实。失败重试保留旧版和手动备注。 |

用合成数据覆盖不同先后、并发和故障点。实施时同步架构契约，执行受影响测试、全量测试和覆盖率门禁。宿主能否在长 Agent 会话期间独立按期触发，需用实际宿主验收。
