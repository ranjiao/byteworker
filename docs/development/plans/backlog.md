# Byteworker 工程 Backlog

本文件只记录已明确延后、仍有价值且具备重新启动条件的事项，不代表当前迭代承诺。
优先级是相对顺序；实施前仍需根据当前架构重新确认范围和验收标准。

## BW-BACKLOG-001：lark-event 自动摄取

- 状态：`deferred`
- 优先级：P2
- 目标：订阅飞书事件流，将新 IM、纪要或文档送入待消化队列，补充现有用户触发的拉取式摄取。
- 启动条件：摄取管线和来源去重契约稳定，且存在持续自动摄取的真实需求。
- 关键风险：后台订阅生命周期、断点恢复、事件去重、授权变化和队列状态治理。
- 验收方向：重复或乱序事件不重复写入；权限和分页不完整时 fail closed；可观测并可安全停用。

## BW-BACKLOG-002：月度知识回顾

- 状态：`deferred`
- 优先级：P2
- 目标：在现有日报、周报之外，汇总一个月内新增事实、决策和变化，形成阶段性认知。
- 启动条件：日报和周报运行收据稳定，用户确认月度回顾的消费场景与投递方式。
- 关键风险：与周报重复、长窗口证据缺失、报告体积和模型成本。
- 验收方向：明确时间窗与 coverage；所有结论可回到来源；不把计划或缺失数据写成已完成事实。

## BW-BACKLOG-003：raw_data 归档与 INDEX 分片

- 状态：`deferred`
- 优先级：P2
- 目标：治理 `raw_data/` 和 `INDEX.md` 的长期增长，同时保持旧引用可解析。
- 启动条件：真实知识库达到既定规模阈值，且当前读取性能或上下文大小出现可测问题。
- 关键风险：归档后引用失效、派生索引与真相源混淆、迁移不可逆。
- 验收方向：迁移可重放、可回滚；旧 provenance 仍可定位；分片索引可由真相源重建。

## BW-BACKLOG-004：纯文本行范围溯源

- 状态：`deferred`
- 优先级：P3
- 目标：在现有 block、comment、message、JSON pointer 等结构化锚点之外，为纯文本来源增加稳定行范围。
- 启动条件：文件级定位在真实核对流程中被证明不足，并能定义内容变化后的锚点稳定策略。
- 关键风险：重排或格式化导致行号漂移，产生“看似精确但已失效”的引用。
- 验收方向：锚点带内容校验或版本绑定；失配时明确降级，不静默指向错误位置。

## BW-BACKLOG-005：知识图谱可视化

- 状态：`deferred`
- 优先级：P3
- 目标：将 `knowledge/` 的实体双链关系导出为可浏览图视图。
- 启动条件：用户确认可视化能改善实际探索任务，而不只是展示效果。
- 关键风险：大图噪声、隐私边界、视图与 Markdown 真相源漂移。
- 验收方向：只读、可重建、有范围过滤；不产生新的业务真相源。
